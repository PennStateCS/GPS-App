Status: **proposal, documentation only** (Phase 1, part C of the surveyor review follow-up). Nothing
here is implemented yet. Companion: [review-response-phase1.md](review-response-phase1.md).

## 3. Proposed architecture

### 3.1 Every position carries its frame and epoch

- New `geokit-core` value types (no Android): `ReferenceFrame` (`ITRF2014`, `ITRF2020`, `NAD83_2011`,
  `NATRF2022`, `PATRF2022`, `CATRF2022`, `MATRF2022`, `WGS84_UNSPECIFIED`) and
  `FramedPosition(lat, lon, h, frame, coordinateEpoch)`.
- `SourcePosition` gains an explicit frame and coordinate epoch; `OutputSystem` names an explicit
  destination frame. The current `GeodeticDatum` stays as a deprecated alias mapping to frames.
- A transformation graph (`FrameTransforms`) composes edges: ITRF2014⇄ITRF2020 (Helmert),
  ITRF2014⇄NAD83(2011) (existing), ITRF2020⇄NATRF2022 (plate rotation + IFDM). Hub frame = ITRF2020.
  Each edge is pinned by PROJ/NGS reference tests, like `ReferencePointsTest` today.
- Epoch handling: the coordinate epoch of a fix is its observation time (as now). Moving a point
  between epochs within a frame (velocity/IFDM) is a separate, explicit step — never implicit.

### 3.2 Receiver feed

- `FixDatum` grows `ITRF2020` and `NATRF2022`; the app's `ReceiverDatum` setting gains matching
  entries ("RTK network (NATRF2022)"). Internal averaging stays in the global frame (WGS84 ≈ ITRF2020),
  as recommended (Q08).
- The NAD83 option stays for networks that have not switched.

### 3.3 Heights

- `VerticalReference` becomes "height model": `ELLIPSOIDAL`, `GEOID18` (NAVD88/PRVD02/VIVD09),
  `GEOID2022` (NAPGD2022), `EGM2008`, `EGM96`, `RECEIVER_REPORTED` (model unknown).
- Label orthometric heights as **H (GEOID18)**, **H (GEOID2022)**, **H (EGM2008)**, **H (EGM96)** —
  never "MSL" (Phase 1 terminology work covers the existing options).
- UTM / outside US coverage: EGM2008 when its grid is available, else EGM96 with a visible notice
  ("EGM2008 not downloaded — using EGM96").
- One geoid per computation: an H is never compared or averaged with an H from another model; the
  stored metadata decides which model an H belongs to.

### 3.4 Grids

- `SpcsZones` keeps SPCS83 unchanged; a parallel `Spcs2022Zones` reads its own table. `TargetSystem`
  gets `StatePlane2022(zoneCode)`. SPCS83 is always on NAD83(2011); SPCS2022 always on NATRF2022 (or
  PATRF/CATRF/MATRF per zone).
- Zone suggestion uses zone **boundaries** (polygons) for both generations, not EPSG boxes.

## 4. Backward compatibility and stored points

Rules:

1. **No silent reinterpretation.** Existing rows keep their numbers; their meaning stays "WGS84 treated
   as ITRF2014" (or NAD83(2011) for `crsEpsg` 6318/6319).
2. NULL in a new column = **unknown / legacy**, resolved at read time to today's behaviour
   (ITRF2014 at `timestamp`); the UI can show "frame: legacy (ITRF2014 assumed)".
3. New captures write the new columns. Exports include them.
4. SPCS83, NAD83(2011) and GEOID18 remain selectable indefinitely; golden tests
   (`CoordinateConverterGoldenTest`, `SpcsZonesTest`, `Geoid18GridTest`) stay unchanged.
5. A schema change touches the off-limits DB schema: it needs explicit approval, an additive Room
   migration (v13 → v14), and migration tests.

Smallest additive schema change (all nullable, no default rewrite):

| Column | Type | Meaning |
|---|---|---|
| `sourceFrame` | TEXT | Frame token of `latitude/longitude/altitude` (`itrf2014`, `itrf2020`, `natrf2022`, …). NULL = legacy |
| `coordinateEpoch` | REAL | Decimal year of the coordinates (normally the observation epoch). NULL = derive from `timestamp` |
| `heightModel` | TEXT | Model of `altitudeMsl` (`geoid18`, `geoid2022`, `egm2008`, `egm96`, `receiver`). NULL = unknown (receiver passthrough today) |
| `receiverDatum` | TEXT (optional) | Feed setting at capture (`itrf2014`, `nad83_2011`, `natrf2022`), for audit |

## 5. Phased plan

| Phase | Scope | Exit criteria |
|---|---|---|
| **1** (now, parallel) | Terminology (H + model, azimuth), accuracy metric, SPCS suggestion, receiver guidance; this roadmap | Reviewed by Dr. Bolkas |
| **2a** | ITRF2020 hub + ITRF2014⇄ITRF2020 edge; `FramedPosition`; schema columns (with approval); EGM96 bundled + EGM2008 download; H labels for UTM | PROJ reference tests ≤ 1 mm; goldens unchanged for legacy inputs; migration test passes |
| **2b** | NATRF2022 frame + IFDM; `FixDatum.NATRF2022` feed option (behind a flag) | NGS NCAT (final) and PROJ agree ≤ 1 cm at CONUS/AK/PR test sites |

## 6. Do not activate until

- [ ] NATRF2022, SPCS2022 and GEOID2022 definitions are **final** (no `beta` in NGS file names) and
      present in a released EPSG dataset **and** a released PROJ / PROJ-data.
- [ ] NGS tools (NCAT, OPUS, geoid computation) are released (not beta) and agree with our code to the
      stated tolerances on reference points.
- [ ] RTK network behaviour is verified in the field: which frame the network (e.g. AlphaRTK) streams,
      the switch date, and what the Emlid Reach reports in GGA before and after (expected after
      ~May 2027 per Dr. Bolkas — **verify with the network operator**).
- [ ] Legacy points round-trip unchanged and are labelled as legacy.
- [ ] Dr. Bolkas has reviewed the Phase 2 transformation chain.
